# ADR 0001：聊天文件夹命名时序——日期文件夹为工作区 + slug 子文件夹

- 状态：已接受
- 日期：2026-08-13

## 背景

需求要求聊天区会话在 `Documents/DSH/年-月-日/xxxx/` 下拥有专属文件夹作为文件工作区，其中 `xxxx` 按用户第一句话由 LLM 生成简短的英文描述。

## 约束

DSH 会话的工作目录（cwd）在**创建会话那一刻**写入会话头部并永久冻结，之后无法修改（头部验证、恢复时的 `SessionCwdConflict` 检查、工作区账目按 cwd 归集都依赖它）。而"新会话"按钮必须立即创建会话（空白会话），此时第一句话尚不存在，`xxxx` 无从得知。

尝试过的替代方案：

- 先建临时名文件夹冻结 cwd、第一句话后再改名/搬迁 → 会话头部 cwd 与工作区记录 path 均无法跟随，重启后会话被账目过滤成"游离"。
- 先无 cwd 创建会话、第一句话后补建 → cwd 冻结后无法补写。
- 拦截 composer 首条消息、先建文件夹再创建会话 → 需要深度侵入会话创建流程，脆弱。

## 决策

采用两段式：

1. 点"新会话"立即创建会话，cwd 冻结为 `Documents/DSH/YYYY-MM-DD/`（日期文件夹，每天一个，在侧边栏"工作区"区域隐藏）。
2. 第一句话发出后，宿主端用 LLM 生成 2–4 个英文小写单词的 slug（失败回退本地规则），创建 `Documents/DSH/YYYY-MM-DD/xxxx/` 子文件夹并写入 `.dsh-chat.json` 标记；通过系统提示让 agent 把该会话的文件读写默认放在该子文件夹。

## 后果

- 优点：文件夹命名完全满足"按第一句话生成英文描述"；会话创建流程零侵入；每聊一个文件夹、可读可写、防冲突（重名自动加 `-2`）。
- 代价：DSH 意义上的"工作区"是日期文件夹而非 `xxxx` 子文件夹，agent 工具默认 cwd 是日期文件夹（由系统提示补偿引导）；已归档会话列表暂时以会话时间而非归档时间展示（归档集合是纯 id 数组，无时间戳）。
- 聊天文件夹归属关系由文件夹内的 `.dsh-chat.json` 标记自描述，重启后扫描重建，无额外中心化存储。
